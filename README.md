# 캐스팅 스와이프

소규모 제작팀과 배우가 휴대전화에서 배역 지원과 후보 검토를 진행하는 **모바일 PWA 첫 구현**입니다. 제품 범위는 [PRD](PRD.md), 화면 의도는 [UI·채팅 명세](docs/UI_CHAT_SPEC.md)를 기준으로 했습니다.

## 실행

Node.js 24 이상과 pnpm이 필요합니다.

```bash
pnpm install
cp .env.example .env.local
```

`.env.local`의 `SESSION_SECRET`을 24자 이상의 긴 임의 문자열로 바꾼 뒤 실행합니다. 이 작업 공간에는 로컬 테스트용 `.env.local`이 이미 생성되어 있습니다.

```bash
pnpm dev
```

`http://localhost:3000`에서 **제작자** 또는 **배우**를 선택합니다.

- 제작자: `/studio` — 접근 코드 없이 바로 열립니다
- 배우: `/actor` — 모집 중인 배역 목록, 이 기기에서 지원한 내역(로컬 저장)

첫 실행에는 **샘플 배역과 가상 지원자 6명**이 생성됩니다. 샘플 생성을 끄려면 `.env.local`에 `SEED_DEMO=false`를 추가하고 새 데이터베이스로 시작하세요. 데이터는 `data/casting.sqlite`에 저장되고 Git에 포함되지 않습니다.

## 현재 작동하는 흐름

- 배역 생성, 마감·재개, 배역별 지원 링크
- 모바일 배우 지원서와 접수 현황 링크
- 지원자 목록, 검색·조건 필터, 내부 검토 상태와 메모, 오디션 후보 목록
- 제작자가 별도로 확정하는 배우 공개 결과
- 지원자별 메시지, 오디션 시간 제안, 배우 시간 선택, 제작자 최종 확정
- 웹 앱 매니페스트, 아이콘, 홈 화면 실행 설정, 오프라인 전송 차단

## 시범 운영 전 필요한 작업

현재 저장소는 **로컬 SQLite**입니다. 여러 기기에서 실제 지원을 받을 서버 운영과 배포에는 팀이 백엔드·호스팅을 결정하고 영속 저장소를 연결해야 합니다. [권장 스택](docs/STACK_PROPOSAL.md)은 Next.js + Supabase입니다. **현재 제작자 화면에는 인증이 없어** 서버에 접속할 수 있는 누구나 지원자 개인정보를 볼 수 있습니다. 외부에 공개 배포하기 전에 반드시 제작자 인증과 팀별 권한을 추가해야 합니다.

사진은 파일 업로드가 아닌 URL 입력이며, 이메일·푸시 알림은 아직 발송하지 않습니다. 채팅은 화면이 열려 있을 때 8초 간격으로 새 내용을 확인합니다. 일정 변경·취소·중복 시간 충돌 방지는 후속 작업입니다. 지원자는 접수 완료 화면의 비공개 링크를 보관해야 현황과 대화를 다시 열 수 있습니다. 실제 개인정보를 받는 공개 서비스로 배포하기 전에 인증, 권한, 저장·삭제 정책, 업로드, 알림을 완성해야 합니다.

## 확인 명령

```bash
pnpm typecheck
pnpm test
pnpm build
```

화면은 390×844 모바일 뷰포트에서 `배역 보기 → 지원 → 접수 확인 → 제작자 검토 → 결과 공개 → 연락 → 시간 선택 → 확정`을 직접 확인했습니다.
