# MVP 구현 백로그

**상태:** 기술 스택 승인 전 실행 초안  
**제품 범위:** [PRD](../PRD.md) R01~R10·R17  
**설계:** [기술 설계](TECHNICAL_DESIGN.md) · [데이터와 API 계약](DATA_API_CONTRACT.md)

작업은 **사용자가 끝까지 수행할 수 있는 흐름** 단위로 나눈다. 담당자와 날짜는 팀 회의에서 정하고, 완료는 코드 병합과 검증 기록을 기준으로 판단한다. P1·P2는 시범 운영 결과를 보고 별도 백로그로 만든다.

## 0. 착수 조건

- [ ] D01~D06 중 첫 구현에 필요한 결정을 [협업 문서](COLLABORATION.md)에 기록한다.
- [ ] 시범 운영용 가상 프로젝트·배역·배우 데이터와 실제 참여자 모집 계획을 구분한다.
- [ ] 팀의 공통 개발 명령, 환경 변수 이름, 비밀값 관리 위치, 테스트·배포 환경을 문서화한다.
- [ ] 제품 코드를 생성한 뒤 이 백로그의 실제 파일 경로·명령을 갱신한다.

## 2. 권장 PR 단위

큰 화면·API·DB 변경을 한 PR에 모두 넣기보다, 위 작업의 수용 기준을 직접 확인할 수 있는 세로 단면으로 제출한다. 예를 들어 DEV-03은 공개 배역 화면, 게시 API, 상태 제약, 권한 검사를 함께 포함한다. 미완성 기능을 기본 화면에 노출해야 한다면 기능 표시를 끄고 병합한다.

각 PR에는 다음을 적는다.

1. 연결된 `DEV-xx`와 `Rxx`.
2. 사용자가 할 수 있게 된 동작과 제외된 동작.
3. DB·API 계약 변경 및 마이그레이션 방법.
4. 직접 수행한 테스트 명령·브라우저 경로·결과.
5. 화면 변경 시 제작자·배우 모바일 캡처와 실제 휴대전화 확인 결과.
6. 권한·개인정보에 영향이 있으면 허용·거절 사례.

## 4. 시범 운영 출구 기준

- [ ] 실제 제작자·배우가 `게시 → 지원 → 검토 → 후보 → 결과`를 도움 없이 완주한다.
- [ ] 권한별 허용·거절 검사와 비공개 미디어 접근 검사가 통과한다.
- [ ] 테스트 사용자 최소 5명의 과업 완료 여부와 막힌 지점을 기록한다.
- [ ] 동일한 후보 10명에 대한 기존 방식·제품 방식 검토 시간을 비교한다.
- [ ] 계획서 목표인 검토 시간 30% 단축과 과업 완료율 80%의 달성 여부를 수치로 보고한다. 미달성 시 원인과 다음 개선을 기록한다.
- [ ] 수집한 개인정보와 파일의 보관·삭제 운영 방법을 팀이 실행할 수 있다.
- [ ] iPhone과 Android에서 설치 전후의 지원 링크·제작자 흐름을 확인한다. 네트워크 연결이 끊기면 미전송 상태가 분명하다.

## 5. 다음 단계 후보

시범 운영에서 어떤 병목이 큰지 확인한 뒤 [PRD의 P1](../PRD.md#6-기능-요구사항)을 재정렬한다. 셀프테이프 자동화, 팀 공동 평가, 오디션 일정, 칸반 보드 중 실제 과업 시간을 가장 많이 줄이는 것부터 별도 계획을 작성한다.
