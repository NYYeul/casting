# 주요 화면과 채팅 UI 시안 명세

**상태:** 모바일 PWA 화면 설계 초안  
**근거:** [PRD](../PRD.md) · [레퍼런스 조사](UI_REFERENCE_RESEARCH.md)

## 1. 화면 지도

| 화면 | 사용자·기기 | 핵심 질문 | 주요 행동 | 단계 |
| --- | --- | --- | --- | --- |
| U01 프로젝트·배역 홈 | 제작자 모바일 PWA | 어느 배역에 검토할 지원자가 쌓였나? | 배역 열기·지원 링크 복사 | MVP |
| U02 지원자 검토 | 제작자 모바일 PWA | 누구를 오디션 후보로 남길까? | 조건 필터·자료 검토·내부 상태·후보 추가 | MVP |
| U03 최종 후보 목록 | 제작자 모바일 PWA | 오디션할 5~10명의 준비 상태는? | 확인 누락 검토·오디션 대상 확정 | MVP |
| U04 배역 지원 | 배우 모바일 | 조건이 맞고 믿고 지원할 만한가? | 촬영 조건 확인·자료 제출 | MVP |
| U05 내 지원 현황 | 배우 모바일 | 내 지원은 접수됐고 다음 결과는 언제인가? | 공개 상태 확인 | MVP |
| U06 연락·오디션 일정 | 제작자·배우 모바일 PWA | 시간·장소·준비물이 서로 확인됐나? | 일정 제안·선택·변경·대화 | 후속 P1 |

### 화면 간 이동

`U01 배역 홈 → U02 지원자 검토 → U03 후보 목록 → U06 오디션 연락`  
`U04 배우 지원 → U05 내 지원 현황 → U06 오디션 연락`

MVP에서는 U03에서 오디션 대상 여부를 확정하고 이메일로 알릴 수 있다. U06은 그 뒤의 일정 조율을 구체화한 시안이며 구현 착수는 시범 운영 결과로 결정한다.

## 2. 주요 화면 구성

### 공통 모바일 구조

- 핵심 화면은 휴대전화 세로 방향에서 먼저 설계한다. 넓은 화면은 같은 흐름을 확장하되 필수 정보가 데스크톱에서만 보이게 만들지 않는다.
- 제작자 하단 탐색은 `프로젝트`, `지원자`, `후보`, `연락`을 후보로 둔다. 현재 단계에 해당하는 1차 행동만 화면 하단에 고정한다. 실제 탭 수는 시안 테스트에서 줄일 수 있다.
- 배우는 외부 지원 링크에서 곧바로 배역 정보를 볼 수 있다. 홈 화면 설치와 로그인을 첫 화면의 필수 관문으로 만들지 않는다.
- 긴 목록과 상세 자료를 동시에 억지로 두지 않는다. `목록 → 상세 → 이전 위치 복귀`가 가능하고, 필터·스크롤 위치를 유지한다.
- 필수 조건·상태는 색만으로 구분하지 않고 텍스트를 함께 쓴다. 주요 터치 영역은 좁은 화면에서 실수 없이 누를 수 있게 띄운다.

### U01 프로젝트·배역 홈

- 상단: 프로젝트명, 제작 유형, 진행 상태, `새 배역`.
- 배역 행: 배역명, 마감, 전체 지원, 미검토, 관심 후보. 최근 접수 시각은 상세에서 확인한다.
- 행 행동: `지원자 보기`, `지원 링크 복사`. 숫자만 크게 나열하기보다 다음 해야 할 일을 표시한다.
- 빈 상태: `배역을 등록하고 지원 링크를 공고에 붙여보세요`.

### U02 지원자 검토

- 첫 화면: 배역 제목·지원자 수·검색·필터와 스캔 가능한 세로 목록. 각 행에는 사진, 이름, 필수 조건 요약, 검토 상태, 자료 유무를 보인다. 필터는 `미검토`, `조건 미확인`, `관심`, `보류`를 우선한다.
- 지원자를 열면 전체 화면 상세로 이동해 사진, 연기 영상, 관련 경력, 조건별 `충족/불충족/미확인`을 순서대로 보여준다.
- 화면 하단 고정 행동: `제외`, `보류`, `관심 있음`. `후보에 추가`는 관심 상태에서 별도 확인한다. 내부 메모에는 배우에게 공개되지 않는다는 설명을 둔다.
- `카드로 보기`는 빠른 순차 검토용. 목록과 상태·필터가 공유되고, 뒤로 돌아와 직전 결정을 고칠 수 있다. 제스처만으로 결정을 강제하지 않고 버튼을 제공한다.
- 사진이나 영상이 없으면 회색 가짜 콘텐츠를 만들지 않고 `자료 없음`으로 표시한다.

### U03 최종 후보 목록

- 후보마다 `촬영 가능`, `참여 의사`, `연기 자료` 확인 상태를 한 줄씩 보여준다. 여러 후보 비교는 요약 목록과 개별 상세 이동으로 수행한다.
- 미확인 항목이 있으면 `확인 요청` 또는 수작업 확인 기록을 남긴다.
- `오디션 대상 확정`은 공개 상태와 알림이 바뀌는 별도 확인 단계다. 후보 목록에 넣는 행동만으로 배우에게 통보하지 않는다.

### U04 배우 지원

- 첫 화면에 배역·촬영일·장소·출연료·교통/식비·제작자·지원 마감·결과 안내 예정일을 읽기 쉽게 배치한다.
- 지원서는 프로필, 사진, 연기 영상 링크, 촬영 가능 여부, 참여 의사로 구성한다.
- 제출 전 필수 누락과 링크 형식을 확인하고, 제출 후 접수 시각을 보여준다.

### U05 내 지원 현황

- 각 지원에는 프로젝트·배역·접수 시각·현재 공개 상태·결과 안내 예정일을 표시한다.
- 내부 `보류`, `관심 있음`, 팀 메모, 다른 지원자 순위는 표시하지 않는다.
- 결과 예정일이 변경되면 현재 날짜와 변경 기록을 구분한다.

## 3. U06 연락·오디션 일정 화면

### 진입과 권한

- 제작자는 **해당 배역에 지원한 배우**의 후보 카드에서 `연락하기`로 들어간다. 배우는 본인이 오디션 대상으로 확정되었거나 제작자가 명시적으로 연락을 시작한 경우에만 대화를 본다.
- 한 대화는 `프로젝트 + 배역 + 지원자`에 묶인다. 여러 배역에 지원한 배우라도 대화와 일정은 배역별로 분리한다.
- 제작자의 내부 평가·메모·다른 후보 정보는 대화에 노출하지 않는다.

### 레이아웃

| 제작자 모바일 | 배우 모바일 |
| --- | --- |
| 대화 목록에서 `배역·배우 이름`, 미응답 일정, 마지막 메시지를 요약. 대화를 열면 상단에 현재 일정 상태, 가운데 메시지·일정 카드, 하단에 `시간 제안`과 메시지 입력 | 상단에 배역·제작자·현재 일정 상태. 가운데 메시지·일정 카드, 하단에 현재 필요한 한 가지 응답과 메시지 입력 |

대화 헤더에는 `단편영화 〈봄날〉 · 민수 역`, 상대 이름, 공개된 오디션 상태를 표시한다. 현재 확정 일정은 대화 상단에서 접고 펼칠 수 있으며, 스크롤 중에도 다시 찾기 쉬워야 한다. 내부 상태 배지는 제작자 화면에만 둔다.

### 메시지 종류

| 종류 | 화면 표현 | 필요한 데이터 |
| --- | --- | --- |
| 일반 메시지 | 발신자별 말풍선, 발송 시각 | 본문, 발신자, 시각, 발송 상태 |
| 오디션 제안 | 날짜·시간대·방식(대면/온라인)·장소·준비물, `시간 선택` 버튼 | 제안 ID, 시간 후보, 장소, 준비물, 응답 기한 |
| 배우 응답 | `14:00 선택`, `참석 어려움`, `시간 변경 요청` 중 하나를 명확히 표시 | 응답 종류, 선택한 시간, 의견, 시각 |
| 일정 확정 | 대화 상단 고정 카드와 시스템 메시지 | 확정 시각, 장소, 버전, 양측 확인 상태 |
| 일정 변경 | 이전·새 시간과 이유, 다시 응답해야 하는지 표시 | 변경 전후 값, 변경자, 알림 상태 |
| 취소 | 취소 주체·시각·사유, 현재 일정 무효 표시 | 취소 상태와 기록 |

시스템 메시지는 채팅 텍스트와 시각적으로 구분한다. 일정 카드를 보냈다는 사실만으로 `확정`으로 표시하지 않는다.

### 제안부터 확정까지

1. 제작자가 날짜·시간 후보 2~3개와 방식·장소·준비물·응답 기한을 입력하고 미리 본다.
2. `제안 보내기`를 누르면 배우에게 알림을 예약하고 대화에 `응답 대기` 카드가 생긴다.
3. 배우는 가능한 시간 하나를 선택하거나 `다른 시간 요청`·`참석 어려움`을 누른다.
4. 배우의 선택은 제작자에게 `선택됨`으로 보인다. 동시간대 중복 여부를 확인한 뒤 제작자가 `일정 확정`을 누르면 양쪽 화면에 같은 확정 카드가 표시된다.
5. 장소·시간을 바꾸면 기존 카드를 덮어쓰지 않는다. 새 버전과 변경 사유를 표시하고, 배우의 재확인이 필요한지 명시한다.
6. 발송 실패는 `전달 실패`로 남겨 재시도한다. `발송`, `읽음`, `응답`, `확정`을 서로 다른 단계로 취급한다.

### 화면 문구 예시

- 제작자 제안: `민수 역 오디션 시간을 제안합니다. 가능한 시간을 골라주세요.`
- 배우 응답: `10월 15일 목요일 오후 2시가 가능합니다.`
- 변경 요청: `제안된 시간에 참석하기 어렵습니다. 다른 시간을 요청합니다.`
- 확정: `오디션이 확정됐습니다 · 10월 15일 목요일 오후 2시 · 서울 마포구`
- 변경: `오디션 시간이 변경됐습니다. 새 일정을 확인해주세요.`

예시 날짜는 시안용 가상 데이터다. 실제 화면은 프로젝트의 일정과 한국 시간대를 사용한다.

## 4. 일정 상태와 예외

| 상태 | 제작자에게 보이는 표현 | 배우에게 보이는 행동 |
| --- | --- | --- |
| 초안 | 아직 전송되지 않음 | 표시 안 함 |
| 제안 발송·응답 대기 | 응답 대기, 보낸 시각 | 시간 선택·변경 요청·참석 어려움 |
| 배우 시간 선택 | 선택한 시간, 확정 필요 | 선택 내용 확인, 확정 대기 |
| 확정 | 확정 시간·장소 | 일정·준비물 확인 |
| 변경 요청 | 요청 사유와 재제안 행동 | 새 제안 대기 또는 요청 내용 확인 |
| 변경 후 재확인 | 이전/새 일정, 재확인 필요 | 새 일정 확인·응답 |
| 취소 | 취소 이력 | 취소 안내와 현재 일정 없음 |

- 제안의 응답 기한이 지나면 `기한 경과`로 표시하되 자동으로 거절하지 않는다.
- 두 배우가 같은 제한된 시간대를 고르는 경우, 최종 확정 때 중복을 막고 대체 시간을 제안한다.
- 자유 채팅으로 `2시 괜찮아요`라고 썼더라도 일정 상태는 자동 변경하지 않는다. 구조화된 버튼 또는 제작자의 명시적 확정이 필요하다.
- 장소가 바뀌면 기존 확정 카드에 덮어쓰지 않고 변경 이력을 남긴다.
- 채팅이 구현되기 전에는 외부 연락 수단을 기록할 수 있지만, 배우에게 `앱에서 확정됨`이라고 표시하지 않는다.

## 5. 사용성 테스트 과제

1. 제작자에게 지원자 12명 중 조건 미확인자 2명과 관심 후보 3명을 찾고, 1명에게 오디션 시간 두 개를 제안하게 한다.
2. 배우에게 모바일에서 제안을 읽고 가능한 시간을 선택하거나 변경을 요청하게 한다.
3. 제작자에게 변경 요청을 확인하고 새 시간을 보내게 한다.
4. 양측에 `현재 확정된 시간`을 물어 답이 일치하는지 확인한다.
5. 내부 메모·보류 상태가 배우 화면에서 보이는지와, 알림 실패를 제작자가 알아차리는지 확인한다.
6. iPhone과 Android에서 설치 전 브라우저와 설치형 PWA로 같은 과업을 수행하고, 연결이 끊긴 동안 보낸 메시지가 성공으로 오인되지 않는지 확인한다.

**관찰 지표:** 과업 완료 여부, 잘못된 확정 인식, 현재 일정 찾는 시간, 주요 버튼 이해도, 재안내 누락. 디자인 선택은 이 결과와 팀 피드백을 반영해 확정한다.
