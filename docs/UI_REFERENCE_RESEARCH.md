# 주요 화면 UI 레퍼런스 조사

**조사일:** 2026년 10월 13일  
**목적:** [PRD](../PRD.md)의 제작자·배우 모바일 PWA 흐름과 후속 채팅·오디션 일정 화면 설계

## 1. 조사 범위와 판단

공식 서비스 소개와 도움말에 나온 **화면 구조·상태·업무 흐름**을 조사했다. 실제 로그인 화면을 사용성 테스트한 결과는 아니며, 우리 사용자에게 필요한지 여부는 시안 테스트로 확인한다. 팀이 제공한 기존 이미지 자료는 배역 조건 검토, 지원자 목록·칸반, 배우 지원 상태, 시간 선택의 초벌 구조로 사용한다.

## 3. 우리 화면에 필요한 설계 원칙

1. **배역 맥락을 놓치지 않는다.** 지원자 카드와 채팅 모두 프로젝트·배역 이름, 촬영일, 현재 공개 상태를 보여준다.
2. **목록에서 행동으로 이어진다.** 지원자 검토 중 `후보에 추가`, `오디션 연락`이 명확하지만, 내부 평가 변경만으로 배우에게 연락하지 않는다.
3. **메시지와 일정은 다른 객체다.** 자유 대화 안에 날짜를 텍스트로만 묻지 않고, 일정 제안 카드에 시간·장소·응답 상태를 구조화한다.
4. **발송·읽음·확정은 구분한다.** 제작자가 제안을 보냈는지, 배우가 응답했는지, 실제 일정이 확정됐는지를 한 배지로 뭉치지 않는다.
5. **배우의 현재 행동을 먼저 보여준다.** 모바일 채팅 상단에는 `시간 선택`, `변경 요청`, `확정 일정 확인` 중 현재 필요한 한 가지를 우선 배치한다.
6. **기존 이미지의 단순함을 유지한다.** 제공된 목록·칸반 예시처럼 비교 정보를 적게 보여주고, 휴대전화에서는 필요할 때 상세를 연다.

## 4. 조사에서 해결되지 않은 질문

- 소규모 제작자는 채팅 안의 시간 선택과 이메일 링크 중 어느 쪽을 더 쉽게 사용하는가?
- 배우는 `접수`, `오디션 대상`, `최종 결과` 외에 어떤 중간 상태를 알고 싶어 하는가?
- 제작자는 여러 배우에게 같은 안내를 보내되, 개인 답변을 배역별로 관리할 필요가 있는가?
- 실제 오디션 일정 변경 빈도와 취소 안내 실패의 비용은 어느 정도인가?

이 질문은 [화면·채팅 시안 명세](UI_CHAT_SPEC.md)의 사용성 테스트에서 확인한다.
